# GitHub Linux reference qualification

The `github-linux-reference` profile records a named, disposable reference environment: the `conformance` job in `aws-s3-linux.yaml` on GitHub-hosted Ubuntu 24.04 x86-64. It rejects other runner types, distributions, repositories, and workflows. These checks use the runner's reported identity; they are not remote attestation.

The existing S3 Linux job runs the product tests once. The profile then binds their report and artifact hashes to the checked-out source and the installed `/usr/local/bin/asb-s3` binary. The systemd lifecycle fixture measures the live `MainPID`, all four process UIDs, `NoNewPrivs`, zero effective capabilities, and `/proc/<pid>/exe` SHA-256 before exercising drain, restart, emergency stop, and identity renewal. The evidence contains the numeric PID/UID and hash, without process environment or command-line data. Separate existing tests cover S3 backup/restore, full storage recovery, and two systemd container boots.

A second gate runs eleven named durable Human relay and SQLite authority library tests with a synthetic provider. They cover crash recovery without redispatch, concurrent reservations, failed checkpoints, lock cancellation, revocation, unknown reconciliation, and SQLite outbox backup/rollback. This does not test a deployed Human relay daemon or coordinated recovery of relay state, authority state, and an external provider.

The `asb-github-linux-reference-<run-id>` artifact contains the standard `asb-qualification` bundle: committed profile, source commit/tree, check results, bounded logs, and hashes. The environment log records the Actions run/attempt/workflow, runner image/version, kernel, systemd version, and filesystem types for the checkout and service state. The offline S3 log binds the companion `asb-s3-linux-<run-id>` artifact's `qa-result.json`; that report binds its raw test logs and binary. Keep both artifacts together when reviewing a run. The library log records the exact required package/test results and a digest of the captured Go JSON output; raw test output is not published by this profile.

The workflow uses a clean detached source snapshot and verifies the resulting bundle. It does not sign a qualification claim: `qualificationClaim` stays false. A reviewer may separately use the existing qualification signing procedure after reviewing the exact bundle and companion evidence.

Passing this profile establishes only the recorded reference checks. Organization deployment, live email delivery, coordinated relay backup/restore, physical power loss, and long-term leak absence remain unqualified. The optional AWS OIDC/S3 live job keeps its existing explicit opt-in gate. A separate organization-host run and chosen provider fixture are still needed for those claims.
